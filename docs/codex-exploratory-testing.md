## 第二部分：探测式测试（重点，模仿真人找 bug）

### 方法：每页每关键交互做 4 遍
1. **正向**：正常操作，看是否符合预期
2. **反向**：反过来操作（点取消、切回去、不选直接下一步）
3. **快速**：快速连点、快速切模板、快速提交
4. **多样输入**：长/短/中文/英文/空/错别字/emoji/超长

### 怀疑清单（按模块）
**A. 一句话建站全流程**
- 空输入/纯emoji/纯标点（!!!）→ 友好提示不报技术错
- 超长（500+字）→ 截断或提示，不静默丢
- 中英混杂/错别字/口语化 → 能理解不瞎猜
- 模糊需求 → 追问不瞎猜
- 越界请求（抢票脚本/违规）→ 拒答
- 换模板后切板块 → 状态不混乱
- 快速连点生成 → 不重复建站/不报错
- 生成中点刷新 → 数据不丢

**B. 确认页**
- 全隐藏/全显示板块 → 生成结果符合预期
- 切模板后意图摘要是否还匹配

**C. 工作台（精修）**
- 连续改同一槽位5次 → 状态一致预览同步
- 对话说换模板 → 二次确认
- 撤销/重做 → 正确回退
- 中英切换 → 语言不漂移
- 预览加载失败 → 不白屏

**D. 模板选择**
- 分类筛选 → 结果正确
- 预览图都能显示（429场景）
- 快速切分类 → 不卡顿错乱

**E. 全局异常**
- 未配key → 明确提示不崩溃
- 断网 → 友好错误
- 重复提交 → 防重复
- 按钮disabled → 合理

### 交付：探测报告（每发现一个）
```
## [严重度] 模块 - 问题标题
- 场景：哪个页面/流程
- 操作：做了什么（可复现）
- 实际：发生了什么
- 期望：应该怎样
- 修复：改哪个文件、怎么改
```
